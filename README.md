# EIM · 活动邀请函工作台

同事在同一个工作台中编辑邀请函、预览手机页面并发布活动。访客通过独立链接报名。服务端使用 Python 和 MySQL 8.4 InnoDB。

## 在这台 Windows 电脑上启动

双击 `Start-InviteStudio.cmd`，在打开的工作台设置首个管理员账号。也可以在项目目录运行：

```powershell
.\start-studio.ps1
```

工作台地址为 [http://127.0.0.1:5820/](http://127.0.0.1:5820/)。启动器使用带有 Pillow 和官方 MySQL 驱动的 Python，优先选择项目虚拟环境。这台电脑使用项目专用的 `127.0.0.1:13306/invite_studio`，启动器会同时检查并按需启动该 MySQL 实例。实例数据位于 `data/mysql-service/store/`，连接配置位于受 Windows ACL 保护的 `data/mysql-private/`。这两个目录包含业务数据和凭据，请在备份时使用受控位置。

## 生产部署

正式微信短链采用公网 HTTPS 入口，由 Caddy 代理到 Python 服务，业务数据写入独立的 MySQL 库。[部署配置、接入资料和验收步骤](deploy/README.md)

## 在其他电脑上运行服务

使用 Python 3.10 或以上版本。以下命令在项目根目录执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

为工作台分配独立的 MySQL 数据库。将主机、端口、库名、应用账号和密码写入 `data/mysql-private/connection.json`（JSON 字段依次为 `host`、`port`、`database`、`user`、`password`），仅授予该账号此库的 SELECT、INSERT、UPDATE、DELETE 权限。初始化时用单独的维护账号配置，数据库和表使用 utf8mb4。外部 MySQL 可在配置中指定 `ssl_ca`、`ssl_verify_cert` 和 `ssl_verify_identity`。服务启动时检查 MySQL 结构版本。

全新数据库使用以下命令初始化，再启动工作台：

```powershell
.\.venv\Scripts\python.exe tools/migrate_mysql.py --config .\data\mysql-private\maintenance.json --empty-install
.\start-studio.ps1 -PythonPath .\.venv\Scripts\python.exe -OpenBrowser
```

也可以把 MySQL 官方 Windows 压缩包的运行文件放到 `.runtime/mysql/`，使用 `.\.venv\Scripts\python.exe tools/local_mysql.py provision` 创建本机专用实例和随机凭据。数据库仅绑定回环地址。维护账号用于建表和迁移，日常服务使用应用账号。[MySQL 官方 Windows 安装说明](https://dev.mysql.com/doc/refman/8.4/en/windows-install-archive.html)

首次设置完成后，管理员可在工作台的「成员管理」创建账号。服务所在电脑也可使用命令行创建账号，并按提示输入密码：

```powershell
.\.venv\Scripts\python.exe server.py user-add --username colleague --data-dir .\data
```

### 从旧版 SQLite 迁入

冻结旧服务写入并用 SQLite Backup API 制作一致性快照，保留原库。将维护连接指向专用空库，替换下面的快照路径：

```powershell
.\.venv\Scripts\python.exe tools/migrate_mysql.py --config .\data\mysql-private\maintenance.json --sqlite <SQLite快照路径>
.\.venv\Scripts\python.exe tools/migrate_mysql.py --config .\data\mysql-private\connection.json --sqlite <SQLite快照路径> --verify-only
```

账号、会话、草稿、发布快照、报名时的字段及答案、去重标识均随业务表迁入；原记录的显示顺序按原 rowid 保留。数据写入、逐表行数及 SHA-256 校验和迁移标记在同一事务完成。重复执行相同快照只进行核对，目标数据产生变化时会提示差异。原 `studio.sqlite3` 和切换快照供回退使用；恢复旧系统前需处理切换后已写入 MySQL 的数据。

默认地址仅供本机访问。团队接入同一台服务器时，应通过同一个服务地址打开工作台。对外分享的邀请函和后台账号应使用 HTTPS。服务的前台启动命令如下，监听地址和数据目录可按实际部署设置：

```powershell
.\.venv\Scripts\python.exe server.py serve --host 127.0.0.1 --port 5820 --data-dir .\data
```

## 做一场活动

1. 从首页进入「模板库」并排比较建筑年鉴、蓝图坐标、会客手札、启势海报、水墨山岚和神经光谱。六款模板使用同一套中邦七页示例，可切换到同一页对照，点「使用此款」创建可编辑草稿。活动库支持卡片、列表和分页，也可从往期活动复制为新一期。每场活动都有独立的 ID 和名单。首页有多个正在报名的活动时，顶部按活动依次轮播，可手动切换或暂停。
2. 编辑工作区包含三个页签。在「基本信息」填写活动名称、日期、时间和地点。在「逐屏设计」编辑邀请函的每一页，在「表单」配置报名字段和限报规则。「基本信息」和「表单」均在同一个工作区显示手机预览及配置。
3. 保存草稿，预览手机页面和报名表。若提示草稿版本已更新，重新载入活动后再编辑。
4. 发布前核对活动时间、地点、封面、报名时段、表单与限报规则。更新时确认和当前发布版的差异。确认后复制该场的 `/s/短码` 或下载二维码，来宾在开放时段内可报名。更新同一期继续使用原链接和二维码，复制活动后首次发布会分配新短码。「活动数据 → 活动详情 → 报名明细」保留提交当时的字段和答案。

### 发布与分享

活动创建人和管理员可以发布、关闭或重新开放报名，以及下线或恢复上线。团队成员可以协作编辑草稿。活动库和编辑器显示发布状态，有新版草稿时提示待发布。

关闭报名后，访客仍可打开邀请函。下线后，短链接和旧 `/i/活动ID` 均显示下线提示。已有报名和统计保留。更新发布版时，报名和上下线状态继续沿用当前设置。恢复上线时沿用原短码，报名状态按下线前设置恢复。

在「基本信息 → 报名时间」可分别填写报名开始和截止的日期、时间，均按北京时间。开始留空时从发布起计算，截止留空时可手动关闭。已发布活动到达开始时间会从「未开始」切为「报名中」，到达截止时间会变为「已截止」。报名接口按服务器时间检查已发布的时段。手动关闭优先生效，重新开放时继续按已发布的时间判断。修改时间需重新发布，复制为新一期会清空上一期的报名时段。

正式环境通过服务端环境变量 `INVITE_PUBLIC_ORIGIN` 配置分享域名，例如 `https://invite.example.com`，只填写 HTTPS 域名。分享链接、二维码和访客页分享元数据都使用这个域名。留空时使用当前服务地址，可用于本地验收。公众号预留 `INVITE_WECHAT_APP_ID` 和 `INVITE_WECHAT_APP_SECRET`，发布面板显示配置就绪情况，微信 JS-SDK 卡片接入待公众号和域名确定后完成。AppSecret 只配置在服务端环境中。

团队成员可以协作编辑活动。管理员可查看全部活动报名，普通成员可查看自己创建或复制活动的报名。首次初始化提供一场公开往期样例，初始报名名单为空。

### 成员管理

以管理员身份登录，在「成员管理 → 新建成员」填写用户名和角色，生成一次性设密链接。把用户名和链接私下交给成员，由本人设置至少 10 个字符的密码后登录。链接有效期为 24 小时，重新生成会作废旧链接。从团队能访问的工作台地址生成链接，以便成员从自己的设备打开。默认头像取用户名首字。

工作台成员表可查看角色和活动数据范围。调整他人的角色需确认，权限在对方下一次请求时生效。当前账号的管理员角色由其他管理员调整。管理员管理成员并查看所有活动的报名和统计，普通成员可以协作编辑邀请函，并查看自己创建或复制的活动数据。

管理员可重发待设密成员的链接、为其他成员重置密码、停用或启用账号。重置会撤销现有会话，成员完成设密后可重新登录。停用会撤销全部会话，保留原活动、发布和报名数据。重新启用后，已设密成员用原密码重新登录，待设密成员需取得新链接。成员列表展示最近登录时间和 IP，详情展示最近 100 次成功登录。IP 取服务实际收到的连接地址，经过反向代理时记录代理的连接地址，时间按北京时间展示。

活动库、活动数据和活动编辑器显示创建人。每次创建、复制、实际保存修改或发布会记录操作人、时间、版本和变更类别，编辑器与活动详情可查看最近 100 条。旧活动沿用已保存的归属，缺少归属时显示「未记录」。历史日志从部署后开始采集。

### 默认七页样式

可直接打开 [/templates](http://127.0.0.1:5820/templates) 选择。每套依次包含邀请函首页、诚挚邀请、活动议程、会场导航、受邀回执、参会须知、关于承办方。回执在第 5 页直接填写，动态读取活动的报名字段和限报规则。模板库和单款模板预览均使用示例数据，预览提交仅展示回执。

「中邦财智伙伴会」是基于中邦公开材料编写的活动示例。企业标识参考原邀请函；议程结合财云案例、项目路演与商务洽谈。会场图标明深圳金融科技大厦 A 座和高新中地铁站。修改场地时，请同步更新地图、交通说明和导航按钮。[财云系统合伙人大会](https://g.eqxiu.com/s/YHHj4cRb?eip=true) · [资本私享汇](https://b.eqxiu.com/s/cRvLA2tu?eip=true) · [会场点位](https://www.amap.com/place/B0FFG9LEY2) · [地图来源](https://openfreemap.org/) · [OpenStreetMap 版权](https://www.openstreetmap.org/copyright)

### 活动数据

从工作台顶部「活动数据」进入总览，按活动查看浏览量、独立访客、平均浏览时长、报名数和转化率，可按名称和时间筛选。点活动名或「查看详情」查看浏览与报名趋势、报名明细和原始表单答案。也可从活动库直接进入单场详情。

- 浏览量按真正可见的公开邀请函打开次数统计，刷新计为新访问。独立访客按本浏览器保留的第一方随机标识去重，在清除浏览器存储或更换浏览器后会重新计数。
- 平均浏览时长为可见总时长除以访问次数。进入后台暂停计时，约每十秒、页面隐藏及离开时回传。网络中断或强制退出可能丢失最后一次尚未成功回传的时长。
- 抵达末页率为出现过末页的访问占比；访问报名转化率为成功提交报名的访问占比。模板预览、编辑器和离线演示均不计入访问。访问指标从启用时采集，历史报名记录继续计入报名数。
- 最近 7/30 天按北京时间自然日计算。访问按开始日期归属，报名记录按提交日期归属。管理员可查看所有活动，普通成员可查看自己创建或复制的活动。
- MySQL 结构 v1 至 v3 可使用维护账号执行 `.\.venv\Scripts\python.exe tools/migrate_mysql.py --config .\data\mysql-private\maintenance.json --upgrade`。v4 为历史已发布活动分配短码，保留原报名状态。

### 手机预览和封面

「逐屏设计」的手机画布可模拟常见机型或 9:16、9:19.5、9:20 三种比例。访客页面按设备的实际可用空间展示。在「页面设置 → 分享封面」上传和裁剪封面，默认首页图片会引用它；其他图片组件也可以独立上传素材。公开访问的封面随活动发布更新。

### 使用逐屏设计

- 从左侧把图片、标题、段落、表格、分割线、文本框或按钮拖入手机画布，也可点选添加。拖动组件调整位置，拖动四角调整尺寸，方向键可微调。文本框是展示用文字区域；需来宾填写的项目放在「表单」。
- 选中组件后，在右侧修改内容及样式、调整图层顺序，或设置入场动效、持续时间和延迟。表格可直接编辑单元格并增减行列。按钮可打开报名表或链接。
- 从左侧添加、复制或重排页面。在右侧「页面设置」调整当前页的名称、底色和进入该页时的切换动画，点顶部「预览」体验实际翻页。旧邀请函打开时按原内容生成可编辑组件，保存和发布沿用原工作流。

### 每场活动限报一次

在「表单 → 每场活动限报一次」中选择用于去重的手机号字段、微信号字段，或直接新增。选中的字段在报名时必填；同时启用两项时，任一项重复即拒绝提交。服务端按填写的号码判断，同一人使用其他号码不属于身份认证的范围。

新规则在发布时生效。手机号比较会统一全角字符、常用分隔符和大陆手机号的 +86/0086 前缀，微信号比较忽略大小写及首尾空格。切换规则时会核对该场已有报名中对应字段的有效值。若已存在重复，系统提示冲突并保留原发布版。

## 两种运行方式

通过服务地址打开的是共享工作台。通过文件系统直接打开 `index.html` 或已交付的单文件 HTML，是在当前浏览器中保存数据的离线原型。旧原型的报名记录不会自动迁入服务数据库。

## 验证

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

集成测试在真实 MySQL 上为每个用例创建并清理一个随机 `inviteqa_` 前缀的独立库。项目专用实例已生成测试账号配置 `data/mysql-private/test.json`；也可通过 `INVITE_TEST_MYSQL_CONFIG` 指向仅能管理该前缀的测试账号配置。未配置测试库时，数据库集成用例显示为跳过。SQLite 仅用于旧库迁移和迁移测试。ZIP 互通测试还需要 Node.js。设置 `RUN_BROWSER_TESTS=1` 并提供 Playwright 模块及本机 Edge 后，同一命令会运行完整浏览器流程；`PLAYWRIGHT_MODULE` 可指定 Playwright 目录。
